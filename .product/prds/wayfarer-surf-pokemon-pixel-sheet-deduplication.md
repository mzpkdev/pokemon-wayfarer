# Wayfarer Surf Pokémon pixel sheet deduplication

## Intent

Wayfarer needs more room within the 32 MiB GBA ROM limit without removing
content or changing how the game looks. Sixty-one Surf Pokémon have normal and
shiny pixel sheets whose generated bytes are identical. Storing one pixel blob
for each of those pairs frees 430,080 bytes while their separate palettes
continue to produce the intended normal and shiny colors.

Players should see no change. Every Pokémon that can appear as a Surf mount
remains available with the same species or form, size, frames, layering,
movement, and animation behavior.

## Design

Wayfarer shares only the pixel data for the 61 normal/shiny pairs that have
been measured as byte-identical. The approved set contains 58 pairs with
6,144-byte sheets and three pairs with 24,576-byte sheets: Arceus, Lugia, and
Rayquaza.

Normal and shiny presentation remain separate above the shared pixels. Each
variant keeps its existing palette selection, including modern shiny palette
overrides, and its existing frame tables and sprite templates. Species and
regional-form entries keep their current identities and ordering.

The expected ROM reduction is exactly 430,080 bytes (420 KiB). Used ROM and
`__rom_end` both shrink by that amount, and free ROM grows by the same amount,
when compared with an otherwise identical Wayfarer release build. The padded
`.gba` file may remain 32 MiB on disk.

## Boundaries

- The other 78 normal/shiny Surf pixel-sheet pairs remain separate. Similar
  appearance or equal dimensions are not evidence that permits sharing.
- This work does not change who can use Surf, how a Surf user is selected, or
  any field-move, encounter, party, species, or form behavior.
- It does not combine palettes, palette tags, frame tables, sprite templates,
  animations, overlays, or species and form records.
- It does not edit or delete the PNG or palette assets, remove shiny conversion
  rules, or stop producing the generated shiny 4bpp files used by validation.
  The separate normal and shiny art sources remain available to artists.
- It does not deduplicate other graphics or make the build automatically
  alias every pair that happens to compare equal.
- Prerelease save compatibility is unaffected because the optimization does
  not change saved data.

## Maintenance risk

The main risk is silent drift. An artist may intentionally change an aliased
shiny pixel sheet while the build continues to use the normal pixels. A
required source check compares every approved pair and fails before linking
if either file changes independently.

The alias list is reviewed data, not a heuristic. A newly identical pair stays
separate until it is measured and deliberately added. A pair that needs
different pixels must be removed from the list before its art change can
land. This keeps the optimization narrow and makes future exceptions visible
in review.

## Acceptance criteria

1. Exactly the approved 61 pairs share one linked pixel address. The remaining
   78 pairs have separate linked pixel addresses.
2. An otherwise identical Wayfarer release build uses exactly 430,080 fewer
   ROM bytes. Its `__rom_end` decreases by the same amount even if ROM padding
   keeps the `.gba` file at 32 MiB.
3. A test fails if either source sheet in an approved pair no longer matches
   byte for byte, if an approved alias still emits a second pixel blob, or if
   a pair outside the allowlist is aliased.
4. All normal, shiny, and modern-shiny palettes remain separate and select the
   same colors as before.
5. The Surf Pokémon roster, species and form identities, frame tables, sprite
   sizes, overlays, and animation choices are unchanged.
6. Normal and shiny smoke tests pass for representative 4x4 and 8x8 mounts,
   including regional forms and non-aliased controls.
