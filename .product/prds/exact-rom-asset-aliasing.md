# Exact ROM asset aliasing

## Intent

Pokemon Wayfarer needs more usable space within the 32 MiB GBA ROM without
removing content or changing the game. This optimization stores one linked
payload for a small, reviewed set of assets whose generated bytes and decoded
meaning are identical, while preserving every existing identity that refers to
those bytes.

Players must see and hear no change. Species and forms, palettes, tables,
animations, maps, scripts, music IDs, playback, runtime memory use, and save data
remain the same.

## Design

V1 uses explicit allowlists for five independently audited families:

1. the 18 non-Surf Arceus overworld form pixel symbols;
2. the eight live Johto and Alola water-current animation frame pairs;
3. 25 exact battle-environment graphics and tilemap groups;
4. four HNS Bike Shop and Johto Bike Shop payload pairs; and
5. the Kyogre/Groudon and Rayquaza battle-song sequence and voicegroup pair.

Each group retains one canonical linked byte range. Every public member name,
table entry, form identity, environment identity, tileset identity, song ID, and
song-table position remains present and resolves to the same content. Internal
names remain local when they have no ABI role. The implementation does not turn
arrays into pointer objects.

The build regenerates and compares both sides of every approved source pair
before linking. A changed pair fails the build until the pair is made equal again
or deliberately removed from its allowlist. New equal assets remain independent
until a review adds them. This is not automatic global deduplication.

Authored assets remain separate. Arceus form art, regional current frames,
battle backgrounds, both Bike Shop tilesets, and both MIDI sources can therefore
diverge later without reconstructing a deleted source. Palettes and metadata
stay independent except for the Bike Shop palette payload, whose complete 16 by
16 color arrays are byte-identical and semantically interchangeable. The two
Bike Shop `Tileset` descriptors remain distinct.

### Player guarantee

The optimized ROM must be observationally equivalent to its paired baseline:

- every Arceus type and palette displays the same overworld pixels and colors;
- Johto and Alola currents use the same frames, order, timing, VRAM destinations,
  and waterfall slice as before;
- every affected battle environment keeps its own selection rules, palette,
  time-of-day variants, decompression behavior, and presentation;
- the Cianwood, Cerulean, and Goldenrod Bike Shop uses keep their map and tileset
  identities, tiles, metatiles, attributes, palettes, and collision behavior;
- Kyogre, Groudon, and Rayquaza keep their song IDs, song-table entries,
  instrument behavior, looping, priority, and playback; and
- no runtime branch, loader, decompression step, heap allocation, EWRAM or IWRAM
  use, loading delay, gameplay state, or save-format change is added.

## Production opportunity

The source and generated payloads were re-audited at commit `443345f`. A clean
production-equivalent Wayfarer release was built from that revision to determine
which copies were live and independently addressed. Its report had
`rom.used_bytes` 32,878,864 and `rom.end_address` `0x09F5B110`. This establishes
the reproducible independent-emission baseline, but it does not replace the
required same-revision optimized release link.

| Family | Earlier normal-build ceiling | Re-audited source ceiling | Live release ceiling selected for v1 | Decision |
|---|---:|---:|---:|---|
| Non-Surf Arceus overworld forms | 21,828 | 21,828 | 21,828 | Include all 17 redundant 1,284-byte payloads. |
| Regional water-current frames | 24,576 | 24,576 | 12,288 | Include Johto to Alola only. The General FRLG copy is absent from the release ELF. |
| Battle-environment graphics and tilemaps | 17,176 | 21,440 | 21,440 | Include the 25 reconstructed groups. The earlier aggregate omitted 4,264 verified bytes. |
| Duplicate HNS object-event graphics | 14,336 | Not reconstructable | 0 | Exclude. A broad scan found many equal pairs but no reviewed subset supporting 14,336. |
| HNS and Johto Bike Shop tileset payloads | 8,684 | 8,684 | 8,684 | Include tiles, metatiles, attributes, and the proven-compatible palette array, but not descriptors. |
| Kyogre/Groudon and Rayquaza audio | 3,304 | 3,304 | 3,304 | Include one 1,768-byte sequence and one 1,536-byte voicegroup copy. |
| Total | 89,904 | 79,832 before release GC | 67,544 | Provisional exact linked-delta target. |

The 67,544-byte figure is a live-release opportunity ceiling, not an accepted
production saving. An implementation may claim it only after clean baseline and
optimized release links from the same revision, toolchain, configuration, and
flags prove the exact delta in `rom.used_bytes`, `rom.end_address`, linked
`__rom_end`, linker categories, and approved symbol ranges. The padded `.gba`
file size is not a measurement.

The expected category deltas are 30,124 bytes in `graphics`, 3,304 bytes in
`audio`, and 34,116 bytes in `other`. Any different result requires an explained
link-map reconciliation. If a family cannot prove its full expected release
delta, remove that family from v1 and recalculate this PRD and its specifications
instead of offsetting the miss with unrelated work.

## Boundaries

This batch is separate from [PR #48](https://github.com/mzpkdev/pokemon-wayfarer/pull/48),
which owns every normal/shiny Surf pixel alias and its exact 430,080-byte saving.
This PRD does not copy PR #48's allowlist, acceptance math, implementation, or
tests. Portfolio summaries may show both batches, but must list 430,080 bytes for
Surf and at most 67,544 bytes for this batch so the totals are not counted twice.

V1 also excludes:

- active Secret Base and Cable Club compression, unreachable tileset
  definitions, and every other part of the tileset storage optimization task;
- the unreviewed HNS object-event duplicate population;
- map-layout compression and layout blockdata aliasing;
- script or text aliasing;
- trainer back-sprite, icon, or font compression or aliasing;
- general audio compression or any audio pair other than the two named payloads;
- palettes outside the reviewed Bike Shop pair;
- whole `Tileset` descriptors;
- visually similar, decoded-similar but byte-different, unlinked, already folded,
  garbage-collected, or conditionally absent payloads; and
- heuristic, linker-wide, or automatic global deduplication.

No public identity, palette selection, table ordering, animation, source asset,
map, script, behavior, or save format may be removed or merged. Address equality
is allowed only for payload symbols listed by the specifications.

## Maintenance policy

The allowlists are reviewed product data. Each row records the family, canonical
and member symbols, authored and generated paths, complete type and size, owner,
and expected release saving. Validation consumes those rows directly.

An intentional art or audio change follows a simple rule: remove the affected
member from the allowlist in the same change, restore independent payload
emission, and keep both source assets. The build must fail if a source diverges
while its row remains approved. Equal new assets do not join an allowlist without
their own source, semantic, ABI, and linked-release review.

Generic byte-comparison or ELF-inspection primitives may be shared with PR #48
if its implementation lands first. The Surf and Exact ROM manifests, build
targets, expected totals, error messages, and acceptance reports remain separate.

## Risks

- An alias can silently show or play the wrong content after a source edit if the
  build does not regenerate and compare both inputs.
- An incomplete or mismatched C array alias can report the wrong size, violate
  compiler alias rules, or change caller ABI. Every C alias therefore uses the
  complete array type and the target definition in the same translation unit.
- Replacing an array with a pointer object changes the data layout expected by
  callers. V1 forbids that mechanism.
- Static current-frame symbols could be made global merely to support aliasing.
  They stay internal through same-translation-unit static aliases.
- An audio alias at the song header alone can leave duplicate track bytes in the
  ROM. The assembly specification owns the entire sequence-object span and all
  relocation boundaries.
- Release LTO and section garbage collection can invalidate normal-build
  arithmetic. Only paired production-equivalent release links establish savings.
- Similar-looking HNS sprites and tilesets can have different frame, palette,
  collision, decompression, or ownership semantics. V1 admits no scanned pair
  without a reviewed row.

## Acceptance criteria

1. The implementation allowlists contain exactly the groups defined by the
   linked specifications and nothing from the excluded scopes.
2. Every approved source and generated payload pair compares byte for byte, and
   compressed members decode to the same bytes and declared dimensions or record
   count.
3. Every C alias uses a complete matching array type, is emitted in the target's
   translation unit, preserves linkage, and does not introduce a pointer object.
4. Every public asset and audio symbol remains present. Approved members share
   their canonical address and logical size; non-approved controls remain
   independent.
5. Each approved group occupies one linked payload range. The link contains no
   accidental alias outside the allowlists.
6. Clean paired Wayfarer release links prove exact reductions of 21,828, 12,288,
   21,440, 8,684, and 3,304 bytes by family, for 67,544 bytes total, in both
   `rom.used_bytes` and linked `__rom_end`. `rom.end_address` moves by the same
   amount and category deltas reconcile exactly.
7. Divergence, missing-member, duplicate-row, wrong-size, wrong-type, stale-output,
   and forbidden-scope fixtures fail before a Wayfarer link.
8. Normal, release, mechanics, smoke, static-analysis, and E2E configurations run
   the validation wherever they consume an alias manifest.
9. Visual and runtime smoke checks cover every Arceus type palette, Johto and
   Alola currents plus the independent General FRLG control, representative
   aliased battle environments, all three Bike Shop map uses, and the Kyogre,
   Groudon, and Rayquaza music selections. HNS object sprites remain independent
   controls because that family is excluded.
10. ROM behavior, runtime memory maps, heap use, EWRAM, IWRAM, loading latency,
    scripts, maps, gameplay state, and save blocks match the baseline.

## Rollout and rollback

Land validation and manifests first, then one source-boundary family at a time.
Measure a clean release after each family so a failed delta can be removed without
obscuring the others. Enable all approved aliases only after the aggregate paired
proof and smoke matrix pass.

Rollback restores independent payload emission for the affected rows and leaves
the authored assets, tables, IDs, and validation inventory in place. It requires
no save migration, runtime compatibility path, or content conversion.
