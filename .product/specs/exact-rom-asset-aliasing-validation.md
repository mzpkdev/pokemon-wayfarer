# Exact ROM alias validation and release proof

PRD: [Exact ROM asset aliasing](../prds/exact-rom-asset-aliasing.md)
Implemented: No

## Scope

This specification defines the shared source validator, build integration,
linked-output proof, production release measurement, negative tests, runtime
smoke matrix, rollout gates, and later implementation sequence for Exact ROM
Asset Aliasing.

The [graphics specification](exact-rom-asset-aliasing-graphics.md) owns the C
allowlists and alias mechanisms. The [audio specification](exact-rom-asset-aliasing-audio.md)
owns sequence and voicegroup boundaries and aliases. This specification does not
add candidates or change either allowlist.

## Behavior

### Validation tools

Add a Python standard-library package under
`game/tools/exact_rom_aliases/`:

- `validate_sources.py` parses the reviewed manifests, regenerates or checks
  derived payloads, verifies source and decoded equality, and validates source
  definitions and ownership;
- `verify_linked.py` checks ELF symbols, linker-map ranges, category reports, and
  paired-release arithmetic;
- `manifest.py` contains strict parsers and data types shared by those commands;
  and
- `tests/` contains positive and negative fixtures for both commands.

If PR #48 lands first, these commands may import generic manifest parsing,
byte-comparison, process execution, or ELF/map-reading primitives from its host
tooling. They must not import its Surf manifest, expected pair count, expected
saving, test target, or acceptance report. Likewise, Surf validation must not
depend on an Exact ROM alias family being enabled.

The tools run on the host and add no ROM code or data. They fail with the family,
group ID, symbol, source path, generated path, expected and actual size, and the
first mismatch or structural error when available.

### Source and generated checks

`validate_sources.py` performs these checks before any Wayfarer link:

1. Parse exactly the four C manifests and the two audio rows named by the source
   specifications. Reject unknown fields, missing fields, duplicate group IDs,
   duplicate member symbols, canonical-as-member cycles, and a symbol assigned
   to more than one canonical.
2. Reject any path or symbol in the Surf graphics tree, Secret Base or Cable Club
   tilesets, map layouts or layout blockdata such as
   `game/data/layouts/**/map.bin`, scripts, text, trainer back sprites, icons,
   fonts, nonapproved audio, or HNS object-event graphics. Explicitly permit the
   reviewed `game/graphics/battle_environment/**/map.bin` inputs named by the
   battle-environment manifest.
3. Confirm that every canonical and member source is tracked and that every
   generated prerequisite is current. Regenerate into a temporary directory and
   compare with the build-consumed output so a stale generated file cannot pass.
4. Compare exact generated bytes. Hashes may appear in diagnostics, but a stored
   hash alone is not acceptance evidence.
5. Decode every SMOL, SMOL tilemap, and FastSMOL payload with the corresponding
   repository host decoder. Compare decoded bytes with each other and with the
   current raw 4bpp or tilemap input. Validate declared dimensions, tile counts,
   metatile counts, attribute counts, palette row counts, and compression mode.
6. For raw current frames, compare 1,536 bytes and validate 48 4bpp tiles per
   ordinal. For Arceus, validate 12,288 decoded bytes per form and 1,284 encoded
   bytes at the pinned v1 toolchain.
7. For Bike Shop palettes, compare 16 ordered rows of 16 `u16` colors and prove
   that both descriptors use the same palette shape and compressed secondary
   tileset contract. Do not treat concatenated equality alone as semantic proof.
8. Parse source definitions and declarations. Each approved C canonical has one
   `INCBIN` definition; each member has one strong alias of the complete expected
   type; targets and aliases share a translation unit; and no approved member is
   emitted independently in optimized mode.
9. Confirm all owning tables still refer to their original member symbols and
   that palettes, descriptors, environment records, frame tables, species and
   form records, map layouts, song IDs, song-table rows, and callers retain their
   order and identity.
10. Apply the assembly normalization, span, relocation, voicegroup, table, and
    caller checks in the audio specification.

The validator has no discovery mode in a production build. A separate developer
report may list possible equal files, but its output cannot alter a manifest,
source definition, linker input, or acceptance total.

### Build integration

Add a focused Make target named `exact-rom-alias-test`. Its stamp depends on the
validation package, every Exact ROM manifest, every authored input, every
generated member and canonical output, the relevant graphics rules, `midi.cfg`,
the audio generator, and all source files that emit or own aliases.

Make the stamp a prerequisite of every Wayfarer ELF that consumes an alias:

- normal `make BUILD=wayfarer`;
- `make BUILD=wayfarer release` and `syms`;
- the mechanics test ELF built by `make BUILD=wayfarer check`;
- `make e2e`, including the ROM used by smoke and full E2E; and
- static-analysis compilation with `ANALYZE=1 make BUILD=wayfarer debug`.

Keep the focused target in `check` as a directly runnable test. Do not make
standalone Emerald, FireRed, LeafGreen, or HNS builds consume the aliases merely
to share a test target.

Define build-only Wayfarer switches for paired measurement and rollback:

| Switch | Default | Effect |
|---|---:|---|
| `EXACT_ROM_ALIASES` | `1` for Wayfarer | Master compile/link selection. `0` emits every member independently. |
| `EXACT_ROM_ALIAS_ARCEUS` | master | Selects only the Arceus rows. |
| `EXACT_ROM_ALIAS_CURRENTS` | master | Selects only the Johto-to-Alola current rows. |
| `EXACT_ROM_ALIAS_BATTLE_ENV` | master | Selects only the 25 battle-environment groups. |
| `EXACT_ROM_ALIAS_BIKE_SHOP` | master | Selects only the four Bike Shop rows. |
| `EXACT_ROM_ALIAS_AUDIO` | master | Selects only AU01 and AU02. |

Accept only `0` or `1`. The family switches are release-audit controls, not
player settings and not preprocessor configuration saved in the ROM. A
production Wayfarer build enables the master and all five families. Source
validation runs in both independent and alias modes; linked alias assertions run
only for enabled families.

### Negative test matrix

Unit and integration fixtures must fail for:

- one changed source byte and one changed generated byte in every payload codec;
- an equal encoded stream that decodes to a wrong size or wrong declared shape;
- a missing canonical, member, source, generated output, table owner, or audio
  label;
- a duplicate row, duplicate symbol, duplicate group ID, cycle, or conflicting
  canonical;
- a C alias with an incomplete array, wrong element type, wrong dimension, wrong
  byte count, pointer object, weak linkage, cross-translation-unit target, or
  independently emitted member;
- a stale Arceus form output, stale water frame, stale compressed battle asset,
  stale FastSMOL tile stream, and stale generated MIDI assembly;
- a changed MIDI option, track boundary, header boundary, voicegroup record,
  relocation, song ID, table position, or caller;
- a Surf symbol or path, any Secret Base or Cable Club payload, an unreachable
  tileset definition, a map layout or layout blockdata at
  `game/data/layouts/**/map.bin`, script or text data, trainer back sprite, icon,
  font, extra audio object, or HNS object-event sprite;
- the General FRLG current set being added to the release saving even though the
  baseline release has no linked copy; and
- an address collision among nonapproved symbols in the audited namespaces.

Compile-only fixtures exercise the exact project compiler and flags for valid
and invalid C array aliases. The valid fixture includes external `u32`, static
`u16`, and `u16[16][16]` aliases and checks matching ELF sizes. Invalid fixtures
must fail compilation rather than relying on the Python validator alone.
Add a positive scope fixture that accepts only the reviewed
`game/graphics/battle_environment/**/map.bin` inputs from the manifest while the
layout-blockdata fixture above still fails.

Also link the static current-frame fixture with the exact production release LTO
and garbage-collection flags. Its final ELF must contain two `LOCAL DEFAULT`
symbols in `.rom_other`, each with size 1,536 and the same address, backed by one
physical range. This linked fixture is required in addition to the non-LTO
compile check.

### Paired production release procedure

The documentation audit established a clean production-equivalent Wayfarer
release baseline at commit `443345f`. Any implementation must reproduce its own
clean baseline at the implementation revision. Do not disable validation, reuse
a normal ELF, or measure a different code revision.

Use two clean, isolated uberepo task worktrees at the same commit. Run all
release `make` commands from each worktree's `game/` directory. Record:

- commit ID and dirty state;
- compiler, assembler, linker, graphics, compression, MIDI, and Python tool
  versions;
- `BUILD`, `MODERN`, release, LTO, map version, configuration headers, environment
  flags, and accepted ROM baseline; and
- the exact commands and artifact hashes.

Do not run another map-version build concurrently because generated map files are
shared within a worktree. Build the independent-emission baseline with:

```sh
make -j"$(nproc)" BUILD=wayfarer EXACT_ROM_ALIASES=0 release syms
```

Build the optimized release with the same command and
`EXACT_ROM_ALIASES=1`. The alias switch is the only permitted configuration
difference. Preserve these files from both builds:

- `pokewayfarer-release.elf`;
- `pokewayfarer-release.map`;
- `pokewayfarer-release.sym`;
- `pokewayfarer-release-size.json`; and
- `pokewayfarer-release.gba` for runtime tests, not size accounting.

Run five additional optimized links, each with one family switch enabled and all
others disabled. Compare every family against the same independent baseline.
This isolates the required deltas and detects link-order or alignment effects.

### Linked-output proof

`verify_linked.py` consumes the baseline and optimized ELF, map, symbol dump,
size JSON, manifests, and recorded build metadata. It must prove:

1. Both builds use the same recorded revision, toolchain, configuration, flags,
   and accepted baseline except for the documented alias switches.
2. Every baseline-approved C symbol exists at the audited size and each member
   has a distinct baseline address. Audio spans and public header labels match
   their manifest boundaries.
3. Each optimized C member and canonical have equal address, ELF `st_size`,
   section, and complete manifest size. Each symbol retains its declared source
   linkage and its expected same-configuration ELF binding and visibility;
   release LTO may internalize an otherwise external current-frame symbol.
   Internal current aliases remain local, and no public definition is changed
   to static merely to create an alias.
4. Both audio public labels resolve to the same header address, both song-table
   rows contain that address, and only one `0x6E8` sequence-object range is
   linked. Both voicegroups share one address and one `0x600` range.
5. The linker map has one physical payload range per approved group. Multiple
   symbol labels at that range are expected; a second copy is a failure.
6. All relevant nonapproved controls remain independent. This includes the
   General FRLG current frames in configurations where they link, battle
   palettes, both Bike Shop descriptors, representative HNS object sprites, and
   all same-namespace graphics not listed by the manifests.
7. No member outside an approved group gains the same address because of a
   heuristic fold, weak resolution, discarded owner, or accidental manifest
   expansion.
8. The category byte counts reconcile exactly to `__rom_end` in both reports.
   Ignore debug sections, host manifests, source files, unlinked generated data,
   and file padding.

The symbol inventory report contains one row per approved symbol with its family
and group, source path, generated path, ELF section, baseline address and size,
optimized address and size, binding, visibility, owner, canonical, and expected
and measured saving. Commit that report only if repository convention later
establishes a durable evidence location; otherwise attach it to implementation
review artifacts.

### Release arithmetic

The current exact acceptance target is:

| Family | Required `rom.used_bytes` and `__rom_end` delta | Required category delta |
|---|---:|---|
| Arceus | 21,828 | `other`: 21,828 |
| Currents | 12,288 | `other`: 12,288 |
| Battle environments | 21,440 | `graphics`: 21,440 |
| Bike Shop | 8,684 | `graphics`: 8,684 |
| Audio | 3,304 | `audio`: 3,304 |
| All families | 67,544 (`0x107D8`) | `other`: 34,116; `graphics`: 30,124; `audio`: 3,304 |

For each family-only link, `rom.used_bytes`, `rom.end_address`, and linked
`__rom_end` decrease by exactly the family value. The all-family link decreases
by exactly 67,544 bytes and equals the sum of the family-only results. Other
categories do not change.

At the clean documentation baseline of 32,878,864 bytes ending at
`0x09F5B110`, that delta would produce 32,811,320 bytes ending at
`0x09F4A938`. Those optimized absolute values are projections only. A clean
paired baseline at the implementation revision supplies the acceptance values.

Any smaller or larger delta blocks the family until the linker map explains it.
If a payload is already folded, garbage-collected, absent, differently encoded,
or unable to reduce the production link, remove it from v1 and update the PRD
and all exact totals. Do not compensate with padded file size, unlinked data, a
different family, or a normal-build saving.

### Runtime and visual smoke matrix

Run the following against baseline and optimized release or E2E ROMs and compare
behavior and presentation:

| Area | Required cases | Checks |
|---|---|---|
| Arceus | Normal plus all 17 type forms; normal and shiny palette paths where supported | Correct form identity, palette, frame order, direction, follower movement, transitions, hide/show, and no Surf asset use. |
| Currents | One active General FRLG control, one Johto current including the waterfall slice, and one Alola current | Eight-frame order, timing, 48-tile upload, destination tile 416, Johto 12-tile waterfall slice from tile 34, collision, forced movement, and regional palette. |
| Battle environments | Standard and modern Tall Grass (BE07, BE17); Long Grass (BE02, BE13); Pond Water (BE03, BE14); Sand (BE06, BE16); Water and Underwater (BE08, BE10); Rock, Rock Snow, and Mountain Snow (BE05, BE15, BE25); Cave, Snow Cave, Volcano, and modern Cave Water (BE09, BE12, BE18, BE24); Building and Blue Building (BE01, BE11, BE19, BE22, BE23); Stadium, Rayquaza, and modern Sky (BE04, BE20, BE21) | Entry animation, decoded background and tilemap, palette and time-of-day selection, trainer and Pokémon layering, transitions, and return to field. |
| Bike Shop | Cianwood Shop, Cerulean HNS Bike Shop, and Goldenrod Bike Shop | Tiles, all palette banks, metatiles, collision and attributes, doors, NPCs, map transition, and distinct tileset descriptor identity. |
| HNS object controls | HNS and non-HNS Biker plus one 2,304-byte exact scanned pair | Symbols and loaded graphics remain independent; no alias appears. |
| Audio | Rayquaza, Kyogre, and Groudon battle selections | Correct song ID before playback, identical baseline waveform/event trace, instruments, channel count, priority, loop point, transitions, pause/resume, and clean stop. |

Where deterministic frame capture or emulator audio-event tracing exists, compare
hashes against the paired baseline. Manual review remains required for palette,
animation, map, and audio presentation. The smoke fixtures must not add code or
data to the production release configuration.

### Required build and test paths

Run the `make` commands from `game/`:

```sh
make -j"$(nproc)" BUILD=wayfarer exact-rom-alias-test
make -j"$(nproc)" BUILD=wayfarer
make -j"$(nproc)" BUILD=wayfarer release syms
TEST=1 make -j"$(nproc)" BUILD=wayfarer check
ANALYZE=1 make -j"$(nproc)" BUILD=wayfarer debug
make -j"$(nproc)" e2e
```

Then run the emulator suites from the repository root:

```sh
pnpm run smoke
pnpm run e2e
```

Set `SKYEMU_ROM` and `SKYEMU_SYMS` to the generated E2E artifacts for the two
pnpm commands. Also run the independent baseline, each family-only release link,
the all-family release link, and both linked verifiers. Record any repository
CI environment flags such as `UNUSED_ERROR=1` and `DEPRECATED_ERROR=1` in the
paired metadata.

### Implementation sequence for orchestration

The later code change should use these dependent stages:

1. Capture a clean independent-emission release baseline at the implementation
   revision and lock the manifest schema and report format.
2. Implement the shared manifest parser, source validator, negative fixtures,
   build switches, and linked verifier. No alias family starts until this stage
   can reject a deliberately divergent fixture.
3. In parallel, assign separate source owners for: Arceus plus water currents;
   battle environments; Bike Shop payloads; and assembly audio. Each owner edits
   only its manifest and owning source/build surface, runs focused validation,
   and produces a family-only release report.
4. Reconcile all source branches into one integration branch. Run the all-family
   link, symbol and map proof, normal, release, mechanics, static-analysis, smoke,
   and E2E paths.
5. Give an independent read-only reviewer the baseline and optimized artifacts,
   manifests, diffs, arithmetic, ABI evidence, audio boundaries, excluded-scope
   checks, and smoke results. Resolve every correctness, ABI, scope, or arithmetic
   finding before enabling aliases by default.

Downstream measurement and review stages read the artifacts produced upstream;
they must not start from a guessed total or a normal ELF.
